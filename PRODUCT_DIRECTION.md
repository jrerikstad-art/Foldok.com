# PRODUCT_DIRECTION.md — settled decisions (read before proposing changes)

## 0. What this product actually is (the frame everything else serves)
THE PROJECT FOLDER IS THE DATABASE; EVERY DOCUMENT IS A VIEW OVER IT.
Capture + folder connectors are the input side of a project memory;
the compiler renders that memory into whatever document the situation
demands — samsvarserklæring, manual, design basis, progress report.
Index once, document many times: the index is the asset, exports are
the harvest. Compliance documents are the FIRST PAYING VERTICAL, not
the definition. This frame changes how we describe the product; it
changes nothing about the wedge, the milestone test, or the build order.


Decided by founder, July 2026. These questions are CLOSED. Re-open only
with new market evidence, not new enthusiasm.

**North star:** `PRODUCT_VISION.md` (surfaces, lifecycle, roadmap). This file
holds settled GTM and wedge decisions that should not drift with every vision edit.

## 1. Identity: opinionated compiler, not open canvas
Foldok is opinionated by default, sovereign user always.
- The OPINIONS are the product: requirement templates, gap detection,
  correct structure, citation rule. Without them we are a generic
  "smart document builder" competing with Microsoft/Notion/Google.
- The OVERRIDES are the respect: every mapping draggable, every proposal
  rejectable, blocking gaps overridable (logged), own templates importable.
- Two kinds of "open" — do not confuse them:
    DOMAIN openness (any profession, any document type): MAXIMIZED.
    Grammar v2 + template import make any document expressible.
    BEHAVIORAL openness (blank canvas by default): REJECTED as default.
    The blank canvas is the problem we were built to kill.

## 2. The three doors (already built — this is the whole model)
At document creation the user chooses:
    a) System template   — full opinion (launch wedge, all demos, marketing)
    b) Imported template — the USER'S opinion, requirement pills tunable
    c) Free document     — no structural opinion (escape hatch; never
                           marketed, never the demo, never the default)
Engine intelligence (indexing, artifact model, fact traceability,
[MANGLER]) runs in ALL three. The citation rule is identity, not template:
even a free document never invents a number.

## 3. Positioning: a companion to Notion, not a competitor
Notion/Drive/SharePoint are where work LIVES. Foldok is where work
becomes a DELIVERABLE — signed, compliant, traceable, paid. We sit
downstream of every workspace and upstream of every auditor, customer
and examiner. Compilers do not compete with editors.
- Never build: wikis, task management, general note-taking, team chat.
- Happily integrate: read from their storage, export back to it.

## 4. What this settles downstream
- Onboarding: template picker first (wedge templates on top), free
  document visible but last. First-run demo = samsvarserklæring or SJA.
- AI default posture: proactive about structure and gaps, silent about
  content until summoned (EDITOR_SPEC cost law unchanged).
- Marketing: leads with opinions ("knows what must be in it", "says
  what's missing"). Pitch lines in foldok-customer-overview.docx stand.
- Pricing: per-export deliverable pricing, not per-seat workspace
  pricing. We charge for finished documents, not for hosting thoughts.

## 5. The never list (unchanged, restated)
No liability. No stored originals or signed PDFs. No invented values.
No silent AI edits. No subscription requirement. No blank-canvas identity.
